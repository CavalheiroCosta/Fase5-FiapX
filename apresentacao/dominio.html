Domínio dos serviços

Três contextos, uma fronteira cada

A Auth reconhece quem entra. A Video API guarda de quem é o vídeo, em que ponto está e onde está o arquivo. O processor trabalha um vídeo que a Video API já aceitou. Nenhum dos três invade o banco do outro.

Auth API

Usuário, credencial, acesso e token. A conta Adm cadastra os demais. Não há autocadastro.

  • Guid, login, nome, e-mail e hash da senha em fiapx_usuarios.
  • Login sem token. Senha errada e usuário inexistente recebem a mesma recusa.
  • O token carrega login e e-mail, vale 30 minutos e não fica gravado.

Video API

Envio, status, listagem e download. O arquivo mora no storage. O Postgres guarda a referência.

  • Ordem do envio: storage, registro, fila.
  • GET /videos lê lista:{login}. Se a chave não existe, reconstrói pelo Postgres.
  • Download só com concluido. Outro login, vídeo inexistente ou status aberto respondem 404.
  • No erro, o e-mail sai depois da gravação. Se o envio falha, o status permanece erro.

Video Processor API

Quebra o vídeo, monta o ZIP e devolve o resultado. Não atende o usuário.

  • Consome id e caminho. Publica comecou antes do fim.
  • Um frame por segundo, em JPEG, dentro do ZIP.
  • Erro não volta para processamento. Não há nova tentativa.
  • Vários processors, a mesma fila. Vídeos diferentes em paralelo.

As quatro camadas

Auth, Video e processor repetem a mesma divisão. A imagem Docker publica só o projeto Api. Storage, fila, Redis, e-mail e ffmpeg ficam atrás de interface.

Api HTTP. Recebe a requisição e devolve a resposta.
Application Casos de uso. Orquestra o que a regra já decidiu.
Domain Usuário, vídeo, status e as regras que não dependem de infra.
Infra Postgres, storage, fila, Redis, e-mail e a assinatura do token, atrás de interface.

ADRs para citar

A lista inteira está em docs/adrs. Na apresentação, estes seis bastam. Cada um cabe em uma frase.

ADR-001 — Camadas

A Auth, e depois a Video e o processor, separam Api, Application, Domain e Infra. A persistência fica atrás de interface.

ADR-006 — JWT com HMAC

O token é JWT assinado com HMAC-SHA256, não criptografado, com login e e-mail, por 30 minutos. Não há revogação: expirado, autentica de novo. A conta Adm é reconhecida pelo login no token.

ADR-008 — A Video lê o JWT sozinha

A Video API não chama a Auth e não referencia os projetos dela. Confere o HMAC no processo, com a mesma chave. Assim o envio não depende do banco de usuários.

ADR-009 — Contrato do envio e da fila

POST /videos recebe o campo arquivo. A fila processamento leva só id e caminho. O binário não entra no Postgres nem na mensagem. O limite local é 200 MB.

ADR-014 — A listagem sai do Redis

O Postgres continua sendo o registro. lista:{login} é a leitura do usuário. Chave ausente é cache miss: a Video lê o Postgres e preenche de novo. Falha do Redis no envio não desfaz o arquivo nem a fila.

ADR-017 — Dois processors

O Compose sobe a mesma imagem em processor e processor-2, portas 5300 e 5301. Os dois consomem processamento. A marca marca:{id} do ADR-011 impede o mesmo vídeo nos dois. O Prometheus raspa os dois no job processor.
