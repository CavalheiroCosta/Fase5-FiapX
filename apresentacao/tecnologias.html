Tecnologias utilizadas

Stack, CI e CD

Os três serviços são .NET 10 no mesmo repositório. O front é HTML, CSS e JavaScript com Vite, sem framework. O CI já barra o pull request. O CD entra no push da main: publica as imagens e atualiza o ambiente.

O que cada parte usa

Parte Tecnologia
Serviços .NET 10. Auth, Video e processor em Api, Application, Domain e Infra.
Acesso JWT HMAC-SHA256, 30 minutos. Senha com o PasswordHasher do .NET.
Front Vite 6. Página estática. No Compose, o proxy aponta /auth para a Auth e /video para a Video API.
Banco PostgreSQL 16. Um banco de usuários e um de vídeos.
Fila RabbitMQ 3 com o painel de management. Filas duráveis processamento e status.
Storage MinIO, API compatível com S3. Bucket videos.
Processamento ffmpeg, um frame por segundo, JPEG dentro do ZIP.
Cache e marca Redis 7. lista:{login} e marca:{id}.
E-mail local Mailpit. SMTP na porta 1025. A mensagem fica na máquina.
Monitoria Prometheus, Grafana e os exportadores de Postgres e Redis. Cada API expõe GET /metrics.
Execução local Docker Compose na raiz do repositório.
Qualidade SonarCloud no mesmo workflow do build.
Entrega GitHub Actions. Imagens fase5-auth, fase5-video, fase5-processor e a do front.

CI — em todo pull request

Arquivo .github/workflows/ci.yml. Dispara em pull request para a main, em push na main e por workflow_dispatch.

Checkout .NET 10 e Java 17 SonarScanner begin Restore e build Release Testes Auth, Video e processor Quality gate Imagens locais :ci

As tags fase5-auth:ci, fase5-video:ci e fase5-processor:ci provam o Dockerfile. O workflow versionado para antes de enviar a imagem ao registro.

CD — no push da main

O mesmo pipeline continua quando o pull request entra na main. Daqui em diante a imagem deixa de ser só local: vai para o ECR e o EKS troca o deployment. O RabbitMQ permanece no ECS e não entra nesse rollout.

Merge na main Repete o CI Build das quatro imagens Push no ECR com o SHA Rollout no EKS Espera o health
  • Auth, Video, processor e front sobem no EKS com a tag do commit. O processor mantém no mínimo dois pods na fila processamento.
  • Não há job de SQL. O schema de usuários nasce com a Auth e o de vídeos nasce com a Video API, como no Compose.
  • Segredos vêm do Secrets Manager. O pod lê S3 e SES por IRSA. A chave HMAC é a mesma na Auth e na Video.
  • Se o pod novo não fica pronto, o deployment permanece na versão anterior. O painel do Grafana é o mesmo FIAP X.
